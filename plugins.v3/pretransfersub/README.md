# 整理前字幕（PreTransferSub）

在 MoviePilot 把文件搬到目标存储**之前**，趁源文件还在本地盘时完成字幕生成与翻译，
让字幕随视频一次入库。

适用场景：媒体库在网盘（CloudDrive2 / alist 等 FUSE 挂载）上，而下载目录在本地盘。
入库后再处理字幕意味着要把整部片子从网盘重新读回来；在整理前处理则完全走本地 I/O。

## 为什么挂在 TransferIntercept

MoviePilot 的整理顺序是：

```
识别 → 规划目标路径 → 【TransferIntercept】 → 搬运 → 刮削 → TransferComplete
```

刮削发生在搬运**之后**、对着目标目录做，所以「nfo 已生成但文件还在本地」这个状态不存在。
`ChainEventType.TransferIntercept`（`app/modules/filemanager/transhandler.py`，注释为
「在宿主写副作用前执行插件拦截」）是唯一同时满足**源文件仍在本地**且**媒体身份已确定**的时机，
事件载荷里直接带着 `MediaInfo`，比解析 nfo 更可靠。

## 最终形态：拦截 → 排队 → 放行

拦截点是同步调用，插件在里面耗时多久，整理队列就阻塞多久。因此 handler 永远只做状态查询：

1. **拦截** —— 首次见到的文件登记入队并 `cancel = True`，整理线程立刻脱身去处理下一个；
2. **排队** —— 插件自己的后台线程慢慢跑 ffprobe / 抽轨 / ASR / 翻译，产物写在源文件旁边；
3. **放行** —— 跑完调 `TransferChain().do_transfer(...)` 主动重投，再次进入拦截时状态已是
   `DONE`，直接放行；视频与新生成的字幕（`.srt` 属于 `RMT_SUBEXT`，按 extra file 处理）
   在同一批里被搬走。

重投不依赖宿主的 5 分钟定时整理，闭环在秒级完成。

## 当前版本（0.1.0）是探针

**默认只观测，不改变任何整理行为。** 目的是先摸清宿主的真实表现，再落地上面的完整实现。

要回答的三个问题：

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | `cancel` 之后宿主记成「失败」还是「待重试」，会不会推送通知 | 每部片子刷一条整理失败太吵，需要知道要不要做静默 |
| 2 | 同一文件两次进入拦截时，指纹是否稳定 | 指纹是防重入的基础；不稳定会导致无限循环重跑 |
| 3 | `meta` 实际是不是 `None` | `__intercept_transfer` 在 `over_flag is None` 的分支里不传 `meta`，重投时需要知道能不能省略 |

## 用法

1. 只勾「启用插件」，保持「只观测不干预」开启，跑一轮正常整理，在插件详情页看记录表；
2. 要验证取消行为时：关掉「只观测不干预」，打开「拦截演练」，在「演练路径关键字」里填
   某部片子的目录名。命中的文件只会被取消**一次**，之后放行；
3. 再打开「演练后自动重投」，可验证 `do_transfer` 重投是否闭环。

记录表字段：源/目标分别标注「本地」还是「网盘」，用于确认拦截时刻拿到的确实是本地路径。

## 安全性

拦截 handler 整体包在 `try/except` 里，任何异常都就地吞掉并记日志，不会影响宿主整理。
「只观测不干预」开启时，插件从不写 `cancel`，整理行为与未安装插件完全一致。
